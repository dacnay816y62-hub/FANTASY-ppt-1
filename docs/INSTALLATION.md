# 安装与环境

[返回首页](../README.md)

## 获取文件

从 GitHub 仓库页面选择 Code → Download ZIP，解压后保留完整目录。支持 Git 的环境也可克隆仓库：

```bash
git clone https://github.com/dacnay816y62-hub/FANTASY-ppt-1.git
```

私有状态下需要获准账户访问；改为公开后可匿名下载。

## 交给支持 Skill 的宿主

将包含 `SKILL.md` 的整个目录交给宿主的技能安装功能。不要只复制入口文件：其中使用了相对路径读取 `references/`、`assets/` 和 `scripts/`。

不同客户端的技能目录与安装入口可能不同，应使用当前客户端提供的安装流程。安装后确认技能列表识别 `ppt-image-deck`，再发送：

```text
使用 $ppt-image-deck，先读取技能，告诉我此次项目需要哪些输入。
```

如果环境没有 Skill 安装能力，可以要求助手读取本仓库的 `SKILL.md` 并按需读取引用文档；这属于手动加载，不保证自动触发。

## 所需能力

| 能力 | 用途 | 缺失时 |
| --- | --- | --- |
| 文件读写 | 读取规则和保存交付物 | 无法完成文件交付 |
| 图像生成 | 原创氛围、元素演化、模拟空间 | 可先整理结构和素材需求 |
| 网页检索 | 地域、历史、真实区位和图片出处 | 不将未经核实内容写成事实 |
| PPT 创建工具 | 原生文本与图形排版 | 只能提供内容和设计指导 |
| PPT 渲染工具 | 检查真实输出 | 必须说明视觉检查未完成 |

随包 Node 图片合并工具还依赖宿主管理的 `@oai/artifact-tool` 与环境变量，普通本地 Node 环境不能直接保证运行。见[脚本说明](SCRIPTS.md)。

## 字体准备

随包有思源黑体 ExtraLight、思源宋体 Bold 和 Light。制作端和审阅端应具备所选字体；跨设备打开可能发生替换。先做一页中英文字体测试，再扩展整套。不要将“字体放入仓库”理解为“字体自动嵌入 PPT”。

## 升级

保留自己的项目文件和定制规则，再更新技能目录。项目输出建议放在单独目录，避免与仓库资源混在一起。仓库名称与技能调用名称不同是正常情况。
