# 设计工作流程

[返回首页](../README.md)

## 1. 建立可信的项目起点

将信息分为 FACT（事实）、JUDGMENT（判断）、PROPOSAL（提案）、UNKNOWN（未知）。区位、面积、历史和现状有来源；设计判断说明推导；模拟条件明确标注。对应规则见[项目真实性](../references/project-truth.md)。

## 2. 组织设计师的汇报逻辑

完整方案通常由项目解读、设计概念、空间规划、空间设计、材质与陈设构成。概念阶段可用元素提炼和设计手法取代尚未开展的规划与空间章节。目录提供稳定导航，章节数量与实际内容匹配。

历史分析只有在能解释今天的材料、工艺、场所或空间关系时才加入。区位分析讲清位置、到达、周边环境与可确认的机会限制，不以空泛赞美替代信息。

## 3. 将文化转成空间动作

建议推导顺序：来源观察 → 形态或关系提取 → 设计动作 → 使用体验。

例如庭院研究可从边界、内外层次、视线与开口比例出发，转化为入口压缩、转折放景、半透隔断、对景停留。图像应能解释变化，不能只有若干漂亮但无关联的抽象物。

## 4. 建立本项目的视觉语言

先决定纸感或矿物感底色、强调色、字体角色、图片光线和留白比例。一般内容页采用清晰中英文章节标签；封面可用极简大底图或半图渐变。字体有观点、标题、说明的级差，正文不继承封面的大字号。

用不同页型控制节奏：有信息密度的研究页、简洁的单一判断页、图像主导的氛围页、可解释的演化页。参考模板是构图工具，不是每个项目必须重复的顺序。

## 5. 分层制作

生成或检索图片后，尽量将最终标题、正文、编号和图例留给 PPT 原生对象。需要精确编辑的路线、节点、色块另行构建；复杂生成图像不承诺内部可编辑。

极简彩平控制色彩数量，功能区、编号和面积建立对应图例。真实项目依据实际平面；模拟平面注明性质。效果图与对应平面和材质逻辑一致。

## 6. 实际输出审阅

逐页检查文字是否缺失、裁切、重叠和字体替换；检查图像与概念是否对应，地图信息是否保真；最后检查整套节奏。结构脚本提供辅助，不能替代视觉审阅。

## 7. 完成项目结尾

用项目特有的设计愿景收束：可以是空间体验承诺，也可以是概念的最终表达。配合与项目一致的底图和“谢谢 / THANK YOU”，避免所有项目使用同一句空泛口号。
